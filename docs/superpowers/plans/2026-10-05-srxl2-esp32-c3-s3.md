# SRXL2 ESP32-C3/S3 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan. Track the steps below; obtain one independent code review before the final commit.

**Goal:** Enable the existing Spektrum Smart/SRXL2 primary serial protocol on RadioMaster XR1, XR2, XR3, ER12, and ER16 receivers.

**Architecture:** Keep the current protocol, throttle safety, telemetry, UART0, and open-drain GPIO matrix routing. Read the receive state from `status.st_urx_out` on ESP32 and `fsm_status.st_urx_out` on ESP32-C3/S3. Use the existing Espressif UART FIFO and transmit-idle helpers.

**Tech Stack:** C++11, PlatformIO espressif32@6.12.0/Arduino ESP32 2.0.17, ESP-IDF 4.4 SDK, Python standard library, existing Unity tests.

**Spec:** The design brief below and the user's instruction to plan and implement support in this conversation.

## Design brief and constraints

- Reuse the clean `feat/firma-smart-srxl2` branch; it contains the existing SRXL2 implementation and is current with `upstream/master` after fetching.
- Enable only ESP32, ESP32-C3, and ESP32-S3 receiver builds with a configured primary TX pin. Keep ESP8266, transmitters, missing-pin configurations, and unknown ESP32 SoCs unsupported.
- Preserve serial protocol ID 11, AirPort, secondary serial choices, all existing serial protocols, the 174 us bus-idle guard, and throttle/failsafe/neutral requirements.
- Do not alter the RF protocol, add dependencies, introduce a new UART abstraction, or add board-specific protocol code.
- C3 XR1/XR2/XR3 use primary TX GPIO21/RX GPIO20. S3 ER12/ER16 use TX GPIO43/RX GPIO44. SRXL2 uses TX for both directions; do not join RX to TX.
- XR1/XR2/XR3 are serial receivers without native servo connectors; document their need for an external steering decoder/controller. Do not add PWM hardware mappings.
- Deliver software-tested receiver images with exact hardware metadata and no private binding/Wi-Fi options. Hardware commissioning remains a separate, explicitly documented requirement.

## Review focus

- A byte in the FIFO, an unfinished received byte, or a low bus must independently block transmission; an idle bus must allow it on every supported SoC.
- TX completion must still include the shifter and FIFO; the ESC reply window starts only after the stop bit completes.
- Primary UART selection, GPIO input/output/open-drain routing, and low-level helpers must match the installed SDK on all three SoCs.
- Unsupported hardware or an absent TX pin must never advertise or instantiate an operational Smart driver.
- Hardware mappings and image identities must remain receiver-specific, including the original ER6 regression build and the ER12/ER16 differences.
